The swarm can reach one host. You can prove it.

HypDMZ runs a HypSwarm research swarm inside a pod whose only way out is a proxy that allows the model API and nothing else, holds the API key the swarm never sees, decrypts every request to check it, and chains every call into a tamper-evident log. The record the swarm builds is a HypGraph record, served live. Every start ends with the swarm trying to escape, from its own seat, and the pod refusing to run if it can.

The one rule

Egress is allowed by who sends, not by where to. One process may dial out: the proxy's user. Everything else in the pod gets loopback.

All three containers share one network namespace, so a port allowlist would apply to the swarm as much as to the proxy. The floor is an iptables owner match on the socket's UID instead: UID 1001 may resolve names and open the HTTP ports; every other UID, over IPv4 and IPv6, may talk to 127.0.0.1 and nothing beyond it. The swarm reaches the model through HTTPS_PROXY=http://127.0.0.1:8080 or not at all.

How a request leaves

Every HTTPS request is opened, read, and either forwarded or refused.

The swarm's client sends CONNECT. The proxy answers with a leaf certificate it mints under the HypDMZ CA, which only the swarm trusts, so the tunnel is plaintext to the proxy and nothing passes through it unread. A tunnel the proxy cannot open is refused, never passed blind.

Host check

CONNECT host:443 against the allowlist. An unlisted host never gets a tunnel.

default-deny

A leaf cert for the host, signed by the pod's own CA. The key never leaves the proxy.

no CA → no tunnel

Method, path prefix, port, time box, request shape: URL length, query size, no opaque base64 runs, no secrets in the URL.

Hourly caps

Forwarded calls and request megabytes over every rule, sliding hour, from the same policy file. The pod's cap on the process, under HypSwarm's own budget.

The order of events does the work.

A sandbox that becomes safe a moment after the agent starts is not one. In HypDMZ nothing the swarm could use exists until the floor is in place, and the pod checks itself from the inside before it lets the swarm run.

  1. 1
    The controller applies the floor first.Owner-UID rules on OUTPUT, IPv4 and IPv6, the control port closed to all but root and the proxy. If the rules don't apply, it exits, and nothing else will start.
  2. 2
    It publishes LOCKED <fingerprint> on 127.0.0.1:8009.A hash of the live rule set. Every 30 s it recomputes the hash; on drift it logs and re-applies.
  3. 3
    The swarm container waits for LOCKED.Up to 60 s. Without it, the entrypoint exits before any user code runs. There is no window in which the swarm can dial out directly.
  4. 4
    It checks that it cannot write its own code.As the swarm user, with access(2), over site-packages, /usr/local/bin and the entrypoint. Anything writable → it refuses to start.
  5. 5
    It trusts the CA certificate, not the key.The swarm mounts certs/public/ only. The private key stays in the proxy's mount, mode 0600, owned by the proxy UID.
  6. 6
    It runs in a box with edges.Read-only root filesystem; /tmp and its home are size-capped tmpfs; memory, CPU and process count are capped on the cgroup. Only /records and /work persist. A runaway script runs out of room, not the machine.
  7. ✕
    hypdmz up ends by trying to escape. probes, most as the swarm user inside the swarm container and the console pair from the host. One success stops the swarm container; the command exits non-zero. A probe with no report counts as a failure.

Policy is a file

The allowlist lives in git, not in an admin page.

proxy/config/firewall.json 
// default-deny; cloud metadata endpoints blocked by CIDR; two rules.
{
  "name": "model-api-deepinfra",
  "scheme": "https",  "host": "api.deepinfra.com",  "ports": [443],
  "methods": ["GET", "POST"],
  "path_prefixes": ["/v1/openai/"],
  "injects": ["model_api_key"],
  "description": "Inference only. Account, billing and GPU paths stay closed."
}
  • Hot-reloaded, fail-closed. The proxy checks the file's size and mtime at most once a second. A missing or malformed file denies everything until it is fixed, and says so on GET /api/policy.
  • Narrow by default. Host, ports, methods, path prefixes. The DeepInfra key is account-wide, so /v1/me, /deploy/ and billing stay closed even though the key could open them.
  • Guards for broad hosts. "guard": "public_web" makes a rule GET/HEAD only, DNS names on 443/80, public addresses only, no long opaque strings in the URL. expires_at time-boxes a rule; a bad date fails closed.
  • Credentials by name. A rule says which vault entry to inject; the entry's own host scope must agree. The key reaches the proxy once, on the first start, and lives in the vault after that.
  • Reviewable. A policy change is a diff in a pull request. The audit log shows which rule matched every request.
What comes out

A record, not a transcript.

The swarm's only output is a HypGraph record: questions, runs with their code, results with values, claims bound to the measurements they rest on, reviews, and the refusals the record made when a seat overclaimed. It is served live on :8000 while the swarm works, with every model call and tool call in the Live view's lanes, and it is a SQLite file in your state directory afterwards, with its own hash chain.

what a run writes

Facts the record checked

Numbers in a claim must match a registered measurement; "significant" needs the test; a check by the author doesn't count. The instrument re-runs each registered computation in the same locked container before a reviewer sees it.

what the pod writes

Who sent what, where, when

Host, method, path, rule, status, sizes, latency, DLP findings, which credential was injected. Never the body. One chained JSONL file, optional remote sink (Splunk, Loki, anything that takes JSON).

what you keep

Everything, locally

Records, work folders, the vault and the audit live in a machine-local state directory outside the repo and outside cloud-synced folders (doctor fails if it isn't). The pod can be torn down and rebuilt without losing any of it.

Honest limits

Where the protection ends today.

What the host can see

The record UI on :8000 answers to anything on the host's loopback, and the control API's token lives in your state directory, where anything running as you can read it. The pod guards the swarm, not your laptop. The .env fallback for the key passes through --env.

File ownership on Windows and macOS

The state directory is a 9p / virtiofs mount, where modes and owners are not enforced. The swarm cannot read the CA key because it mounts a different directory, which egress-check verifies, not because of a file mode.

What is not capped

/records and /work are host folders podman cannot size-limit. The hourly cap counts calls and bytes, not dollars; the model's price sets those, and HypSwarm's --budget-usd is the finer control. Every run shares one egress identity and one key.

Quick start

From pip install to a verified swarm.

Podman on the host (Podman Desktop on Windows and macOS, podman on Linux) and Python 3.10 for the launcher, which has no dependencies. The three image build contexts, the default policy and an example ride inside the package; nothing is read from a repository checkout.

pip install --pre hypdmz              # the launcher: stdlib only, the pod's build contexts inside
hypdmz init                           # the state dir and its .env; prints what comes next
podman secret create hypdmz_llm_api_key -   # paste the model API key; it reaches the proxy only
hypdmz doctor
hypdmz build                          # three images: controller, proxy, swarm
hypdmz up                             # creates the CA, starts the pod, vaults the key, verifies the floor
hypdmz run first-swarm --python --budget-usd 0.20
hypdmz egress-check --json            # any time; exit 1 on a single bypass

record UI → http://127.0.0.1:8000 · control API → http://127.0.0.1:8002 · proxy for host tools → http://127.0.0.1:8080 · the allowlist → hypdmz policy · your own task → hypdmz example first-swarm ./mine, edit, hypdmz run ./mine

Alpha. HypDMZ runs our own research today. The package is on PyPI; the repository opens once the floor has been verified on Linux and macOS hosts as well as Windows.
